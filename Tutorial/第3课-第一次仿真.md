# 第 3 课：第一次仿真 — 让 X-HEEP 跑起来

## 学习目标

完成本课后，你应该能够：

- 理解 FuseSoC 构建和仿真命令的每个参数含义
- 跑通一次完整的 Verilator 仿真
- 理解仿真流程：RTL + 固件 → 波形 + UART 输出
- 用 GTKWave 观察时钟、复位和 UART 波形
- 理解 testbench 如何例化待测设计（DUT）

## 1. 仿真流程概览

```
┌─────────────┐    ┌─────────────┐
│ SystemVerilog│    │  C 固件代码  │
│   RTL 源码   │    │  main.c     │
└──────┬──────┘    └──────┬──────┘
       │                  │
       │ FuseSoC          │ CMake + GCC
       │ (收集RTL文件)     │ (编译)
       ▼                  ▼
┌─────────────┐    ┌─────────────┐
│ 编译后的 DUT │    │  .hex 文件   │
│ (Verilator   │    │ (RISC-V机器码)│
│  C++ 模型)   │    │              │
└──────┬──────┘    └──────┬──────┘
       │                  │
       └────────┬─────────┘
                │
                ▼
        ┌──────────────┐
        │ 仿真可执行文件 │ ← 由 tb/tb_top.cpp + DUT 编译得到
        └──────┬───────┘
               │ ./Vtestharness +firmware=... 执行
               ▼
        ┌──────────────┐
        │  仿真结果     │
        │ ├── waveform.fst │ → GTKWave 查看
        │ └── uart0.log │ → UART 输出了什么
        └──────────────┘
```

核心流程：**RTL（硬件）和固件（软件）分别编译 → Verilator 把它们合在一起仿真**。

## 2. FuseSoC 命令详解

### 2.1 基本命令

```bash
cd /path/to/x-heep
fusesoc --cores-root . run --target=sim --tool=verilator openhwgroup.org:systems:core-v-mini-mcu
```

逐段拆解：

| 参数                                        | 含义                                                      |
| ------------------------------------------- | --------------------------------------------------------- |
| `--cores-root .`                          | 将当前目录作为额外的 core 搜索根目录                      |
| `run`                                     | 执行构建（setup + build + run）                           |
| `--target=sim`                            | 使用 `sim` target（定义在 `core-v-mini-mcu.core` 中） |
| `--tool=verilator`                        | 使用 Verilator 作为仿真工具（必须显式指定）               |
| `openhwgroup.org:systems:core-v-mini-mcu` | VLN 名（Versioned Library Name），标识要构建的顶层模块    |

### 2.2 常用的额外参数

```bash
# 仅执行到 setup（生成但不编译），查看会收集哪些文件
fusesoc --cores-root . run --target=sim --tool=verilator --setup openhwgroup.org:systems:core-v-mini-mcu

# 仅构建（编译但不运行仿真）
fusesoc --cores-root . run --target=sim --tool=verilator --build-only openhwgroup.org:systems:core-v-mini-mcu

# 仅运行（使用已经编译好的仿真二进制）
fusesoc --cores-root . run --target=sim --tool=verilator --run-only openhwgroup.org:systems:core-v-mini-mcu
```

### 2.3 FuseSoC 的执行阶段

运行 `fusesoc run` 时，内部经历了三个阶段：

```
Setup        → 收集所有 RTL 文件，解析 .core 依赖
             → 生成编译脚本（Makefile）
             → 结果放在 build/<core_name>/ 中

Build        → 执行编译
             → Verilator 将 RTL 变为 C++，再用 g++ 编译成可执行文件

Run          → 执行仿真
             → 加载固件的 .hex 文件到 memory model
             → 跑指定时间或直到 $finish
```

### 2.4 已知问题：Verilator 5.020 chandle bug

当前环境（Verilator 5.020 Debian 包）存在一个代码生成 bug：`chandle` 类型的信号在生成 trace 代码时会产生空的 `VerilatedTraceSigType::` 枚举值，导致 C++ 编译失败。

**推荐做法**：使用项目根目录下的 `build_sim.sh` 脚本，它会自动处理此问题：

```bash
cd /path/to/x-heep
./build_sim.sh
```

如果要用原始命令，需要手动修复：

```bash
# 1. 先运行 FuseSoC（Verilator 编译阶段会失败）
fusesoc --cores-root . run --target=sim --tool=verilator openhwgroup.org:systems:core-v-mini-mcu 2>&1 || true

# 2. 修复 chandle trace bug
BUILD_DIR="build/openhwgroup.org_systems_core-v-mini-mcu_1.0.5/sim-verilator"
sed -i 's/VerilatedTraceSigType::,/VerilatedTraceSigType::LOGIC,/g' "$BUILD_DIR/Vtestharness__Trace__0__Slow.cpp"

# 3. 继续编译
make -C "$BUILD_DIR" -f Vtestharness.mk
```

## 3. 第一次仿真

### 3.1 确保环境就绪

```bash
# 确认所有工具可用
riscv32-unknown-elf-gcc --version
verilator --version
fusesoc --version
```

额外依赖（Verilator 仿真需要）：

```bash
sudo apt-get install -y libelf-dev
```

### 3.2 运行仿真

```bash
cd /path/to/x-heep

# 方式一（推荐）：使用 build_sim.sh 脚本
./build_sim.sh

# 方式二：手动命令（见 2.4 节的修复步骤）
```

构建成功后，进入 build 目录运行仿真：

```bash
cd build/openhwgroup.org_systems_core-v-mini-mcu_1.0.5/sim-verilator
./Vtestharness +firmware=/home/rime/x-heep/sw/build/main.hex
```

### 3.3 解读仿真输出

仿真输出类似：

```
=== X-HEEP Verilator Simulation ===
This simulation runs 21202 clock cycles and exits with code 0.
waveform.fst generated.
```

关键信息：

- **循环数**：仿真执行了约 20000+ 个时钟周期
- **退出码 0**：表示固件正常执行完毕
- **waveform.fst**：生成的波形文件

**注意**：默认固件 `example_gpio_toggle` 中 `PRINTF_IN_SIM` 设为 `0`（仿真时不打印），所以你不会在终端看到 UART 输出。这是为了减少仿真时间。如果想看到 UART 输出，可以修改固件中 `PRINTF_IN_SIM` 为 `1`（见第 6 节）。

## 4. 用 GTKWave 查看波形

仿真结束后，当前目录下会生成波形文件 `waveform.fst`。

### 4.1 确认波形文件

```bash
ls -lh build/openhwgroup.org_systems_core-v-mini-mcu_1.0.5/sim-verilator/waveform.fst
```

### 4.2 用 GTKWave 打开

```bash
gtkwave build/openhwgroup.org_systems_core-v-mini-mcu_1.0.5/sim-verilator/waveform.fst &
```

### 4.3 GTKWave 基本操作

```
┌─────────────────────────────────────────────────────┐
│                    GTKWave 界面                       │
│                                                      │
│  ┌───────────────────┐  ┌──────────────────────────┐ │
│  │  SST (信号树)      │  │  波形显示区               │ │
│  │                   │  │                          │ │
│  │  TOP              │  │  clk   ┌─┐  ┌─┐  ┌─┐    │ │
│  │  ├── testharness  │  │       ─┘ └──┘ └──┘ └─   │ │
│  │  │   ├── clk      │  │                          │ │
│  │  │   ├── rst_n    │  │  rst_n  ┌─────────────── │ │
│  │  │   ├── clk_i    │  │        ─┘               │ │
│  │  │   ├── rst_ni   │  │                          │ │
│  │  │   ├── uart_tx  │  │  uart_tx ────┐  ┌─────── │ │
│  │  │   └── ...      │  │              └──┘         │ │
│  │  └── ...          │  │                          │ │
│  └───────────────────┘  └──────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

**关键操作**：

| 操作           | 快捷键/方法                                 |
| -------------- | ------------------------------------------- |
| 添加信号到波形 | 在 SST 中选中信号 → 点击下方 "Append" 按钮 |
| 删除信号       | 在波形区选中信号 → 按 Delete               |
| 放大/缩小      | 鼠标滚轮 /`+` `-` 键                    |
| 平移           | 鼠标中键拖拽 / 方向键                       |
| 搜索信号       | 在 SST 上方的搜索框输入信号名               |
| 测量时间差     | 鼠标左键点击起点 → 中键点击终点            |
| 信号值转译     | 右键信号 → Data Format → 选择格式         |

### 4.4 需要观察的基础信号

在 SST 中搜索并添加以下信号：

| 信号       | 所在模块          | 要看什么                       |
| ---------- | ----------------- | ------------------------------ |
| `clk`    | TOP.testharness   | 系统时钟频率、是否稳定振荡     |
| `rst_n`  | TOP.testharness   | 复位释放时刻、MCU 何时开始工作 |
| `clk_i`  | TOP.testharness   | 输入到 SoC 的时钟              |
| `rst_ni` | TOP.testharness   | 输入到 SoC 的复位（低有效）    |

> **提示**：Verilator 波形中，顶层 SystemVerilog module（`tb_top`）直接对应 `TOP`，没有额外的 `TOP.tb_top` 层级。`tb_top` 中例化的 `testharness_i` 在波形中显示为模块名 `testharness`。
>
> **在 GTKWave 中找信号**：
> 1. 展开 `TOP` → 往下滚动找到 `testharness`（注意不是 `tb_top`）→ 展开即可看到 `clk`、`rst_n` 等
> 2. 更快的方式：用 SST 面板上方的搜索框，输入 `clk` 过滤信号，然后在结果中选 `TOP.testharness.clk` 添加到波形

## 5. 仿真 Top 结构 — 理解 testbench

仿真环境由以下层次组成：

```
tb_top.sv（顶层 testbench）
│
├── 时钟生成器（产生 clk）
├── 复位生成器（产生 rst_n）
│
├── testharness_i（testharness 模块）
│   │
│   ├── x_heep_system_i（DUT — X-HEEP SoC）
│   │   ├── cpu_subsystem（CV32E40P 核心）
│   │   ├── memory_subsystem
│   │   ├── peripheral_subsystem
│   │   │   ├── uart
│   │   │   ├── gpio
│   │   │   ├── i2c
│   │   │   └── spi
│   │   └── ao_peripheral_subsystem
│   │
│   └── UART DPI 模型（uartdpi — 接收 uart_tx 并写入 uart0.log）
│
└── remote_bitbang（JTAG 远程调试桥）
```

关键点：

- **时钟**：testbench 中用 `#CLK_PHASE_HI` / `#CLK_PHASE_LO` 的方式产生时钟，周期 10ns（5ns + 5ns），频率 100MHz
- **复位**：仿真开始时 `rst_n = 0`，大约 100 个时钟周期后置为 1，MCU 开始执行
- **固件加载**：`tb_top.cpp`（C++ 文件）负责在仿真开始时将 `.hex` 文件加载到 Flash/SRAM 中

可以打开以下文件阅读，搜索 `clk`、`rst`、`DUT` 等关键词理解结构：

- `tb/tb_top.sv` — testbench 顶层
- `tb/testharness.sv` — DUT 封装层
- `tb/tb_top.cpp` — 固件加载和仿真主循环

## 6. 修改固件并重新仿真

### 6.1 开启仿真时的 UART 输出

编辑 `sw/applications/example_gpio_toggle/main.c`，将 PRINTF_IN_SIM 改为 1：

```c
#define PRINTF_IN_SIM   1   // 原来是 0
```

你也可以修改打印内容：

```c
printf("My first X-HEEP simulation!\n");
```

### 6.2 重新编译固件

```bash
cd sw/build
cmake .. -DPROJECT=example_gpio_toggle -DCMAKE_TOOLCHAIN_FILE=../cmake/riscv.cmake -DTARGET=sim
make
```

编译完成后，新的 `main.hex` 会在 `sw/build/` 目录下。

### 6.3 重新仿真（仅重新运行）

如果 RTL 没有改变，可以跳过 RTL 编译阶段，直接运行仿真：

```bash
cd build/openhwgroup.org_systems_core-v-mini-mcu_1.0.5/sim-verilator/

# 使用新编译的固件
./Vtestharness +firmware=/home/rime/x-heep/sw/build/main.hex
```

如果你修改了 RTL，则需要重新构建（再次运行 `./build_sim.sh`）。

## 7. 常见波形信号速查

打开波形后，按以下路径逐步深入观察：

```
层次 1: TOP
  ├── testharness                       ← tb_top 中的 testharness_i 例化
  │   ├── clk                           ← 系统时钟
  │   ├── rst_n                         ← 复位（低有效）
  │   ├── clk_i                         ← SoC 时钟输入
  │   ├── rst_ni                        ← SoC 复位输入
  │   ├── uart_tx                       ← UART 发送引脚

层次 2: TOP.testharness.x_heep_system_i
  ├── core_v_mini_mcu_i                 ← MCU 顶层
  │   └── ...                           ← CPU 子系统等

层次 3: 外设模块
  └── 在 x_heep_system_i 下找到对应外设，观察读写请求/响应信号
```

> **提示**：Verilator 波形中 `TOP` 就是 `tb_top`，`testharness` 就是 `testharness_i` 例化。在 GTKWave SST 中展开 `TOP → testharness → x_heep_system_i → core_v_mini_mcu_i` 即可看到完整的模块层次。

## 课后任务

1. **跑通完整仿真**：用 `build_sim.sh` 跑通一次仿真
2. **查看波形**：用 GTKWave 打开 waveform.fst，找到并观察 `clk`、`rst_n` 的波形
3. **观察 UART 发送**：将 `PRINTF_IN_SIM` 改为 1 并重新编译固件，在波形中找到 UART TX 信号，观察它发送字符时的比特波形。UART 协议：1 起始位（低）+ 8 数据位（LSB 先）+ 1 停止位（高）
4. **修改固件**：修改 `example_gpio_toggle` 的打印信息，重新编译并仿真，确认输出变化（终端输出和 uart0.log）
5. **阅读 testbench**：打开 `tb/tb_top.sv`，找到时钟生成代码（搜索 `forever` 或 `#`），计算仿真中的时钟频率；找到复位生成代码，看复位持续了多少个时钟周期

## 常见问题

### Q: `fusesoc` 报 `ModuleNotFoundError: No module named 'edalize'`

```bash
pip install edalize
```

### Q: Verilator 报 `%Warning` 或大量 warning 导致退出

Verilator 5.x 默认将所有 warning 视为 fatal error。X-HEEP 配置中已添加 `-Wno-fatal` 来抑制此行为。如果仍然遇到，检查你的 `core-v-mini-mcu.core` 中是否包含 `-Wno-fatal`。

### Q: 编译时出现 `expected unqualified-id before ',' token` (chandle bug)

这是 Verilator 5.020 的已知 bug。使用 `build_sim.sh` 脚本可以自动处理。详见第 2.4 节。

### Q: 找不到 `.svh` include 文件

如果 FuseSoC 报告 `Cannot find include file`，这通常是因为 `.core` 文件中 `is_include_file: true` 标记在了目录上而非具体文件上。已在 `pulp_platform_serial_link.core` 中修复。

### Q: 找不到 `-lelf` 链接库

```bash
sudo apt-get install -y libelf-dev
```

### Q: 仿真跑完了但没有波形文件

在当前目录（`sim-verilator/`）下查看是否有 `waveform.fst`。波形文件在运行 `./Vtestharness` 时生成，不在 `fusesoc` 构建阶段生成。

### Q: `uart0.log` 是空的

默认固件 `example_gpio_toggle` 在仿真时不启用 printf（`PRINTF_IN_SIM 0`），所以 UART 不会有输出。将 `PRINTF_IN_SIM` 改为 `1` 并重新编译固件即可。

## 思考题

1. 在波形中，`clk` 的一个完整周期是多少？对应什么频率的时钟？
2. `rst_n` 从 0 变成 1 之后，大约多少个时钟周期后 CPU 开始取指？
3. 如果 UART 波特率是 115200，在波形中每个 bit 的宽度大约是多少个系统时钟周期？（系统时钟 100MHz）
