## 1. 从顶层往下看

X-HEEP 的全部 RTL 的顶层是 `x_heep_system.sv`。但它只例化了 **3 个大块 + 1 个复位同步器**：

```
x_heep_system
├── core_v_mini_mcu_i       ← 整个 MCU（CPU + 总线 + 内存 + 外设）
├── pad_ring_i              ← IO pad 环（60 个引脚）
├── pad_control_i           ← pad 复用控制器
└── rstgen_i                ← 复位同步器（防毛刺）
```

如果类比电脑：`core_v_mini_mcu` = 主板 + CPU + 内存 + 所有外围接口，`pad_ring` = 物理接口（USB 口、网口、HDMI），`pad_control` = 接口切换开关。

### 1.1 pad_control — 引脚复用

`x_heep_system.sv` 里有 20 个 `always_comb` 块，做硬件引脚复用。例如：

```systemverilog
// GPIO 1 可以与 DDR serial link 的接收线复用
assign pad_gpio_1_in = pad_muxes[1] ? ddr_rcv[0] : gpio_out[1];
```

`pad_muxes` 这个数组来自 `pad_control` 模块（MMIO 可读写，地址 `0x20080000`），软件可以在运行时切换引脚功能。

## 2. core_v_mini_mcu — 拆开六大块

`core_v_mini_mcu.sv` 例化了 6 个子模块：

```
core_v_mini_mcu
├── cpu_subsystem_i        ← CPU + X-IF 包装
├── debug_subsystem_i      ← JTAG + SPI 调试
├── system_bus_i           ← 总线互联（master demux + crossbar）
├── memory_subsystem_i     ← 2 个 SRAM bank
├── ao_peripheral_subsystem_i  ← AO 域 12 个外设
└── peripheral_subsystem_i     ← 外设域 8 个外设
```

6 个块的职责：

| 块                      | 一句话                                  | 如果不实例化                            |
| ----------------------- | --------------------------------------- | --------------------------------------- |
| cpu_subsystem           | 取指令、执行指令、响应 trap             | 芯片里没 CPU                            |
| debug_subsystem         | JTAG/SPI 调试，断点、单步、内存查看     | 不能调试                                |
| system_bus              | 把 CPU、Debug、DMA 的请求路由到正确地址 | 所有 master 和 slave 之间不通           |
| memory_subsystem        | 64 KB 片上 SRAM                         | 程序没地方跑（只能跑在 Flash 里，极慢） |
| ao_peripheral_subsystem | 掉电不死的外设（唤醒、计时、DMA）       | 没法休眠，不能 DMA                      |
| peripheral_subsystem    | 跟着主电源的外设（串口、GPIO、I2C）     | 没有 IO                                 |

## 3. cpu_subsystem — CPU 是什么

### 3.1 CV32E20（CVE2）

X-HEEP 默认用的是 **CV32E20**，来自 OpenHW Group。这是一个 **2 级流水线、顺序执行、仅 M-mode** 的 RISC-V 核心。

```
CVE2 特性清单：
├── ISA:        RV32IMC（整数 + 乘除 + 压缩指令）
├── 流水线:     2 级（取指 → 执行）
├── 特权模式:   仅 M-mode（没有 S/U mode）
├── PMP:        禁用（不需要内存保护）
├── 中断:       CLINT 式（软件/定时器/外部/快速 四条线）
├── 调试:       支持 external debug（halt/step/breakpoint）
├── X-IF:       支持自定义加速器扩展接口
└── 面积:       ~15k 门（极小的 MCU 核）
```

文件路径：`hw/vendor/openhwgroup/cv32e20/rtl/cve2_top.sv`

### 3.2 CPU 的对外接口

```
                     ┌──────────┐
                     │ cv32e20  │
    instr_req ──────→│          │──────→ instr_rdata
    (取指令)         │          │
                     │          │
    data_req  ──────→│          │──────→ data_rdata
    (读/写数据)      │          │
                     │          │
    irq_software ───→│          │
    irq_timer    ───→│          │
    irq_external ───→│          │
    irq_fast[15] ───→│          │
                     │          │
    debug_req    ───→│          │──────→ debug_halted
                     └──────────┘
```

CPU 有**两条独立的 OBI 总线**：

- **指令总线**：只读，只用来取指令
- **数据总线**：读写，用来 load/store

这跟第 9 课的图吻合——`cpu_subsystem` 例化后产生两个 master 端口连到 `system_bus` 上："CPU 取指"和"CPU 访存"。

### 3.3 X-IF wrapper — 加速器接口

在 CPU 外面包了一层 `cve2_xif_wrapper.sv`，负责 X-IF 协议版本转换（SoC 用 v1.0，CVE2 核用 v0.2）。

X-IF（CORE-V eXtension Interface）允许**自定义加速器**插入到 CPU 流水线中——当 CPU 遇到特定指令时，发射到 X-IF 口，加速器算完结果再提交回来。相比 OBI 主端口式的加速器（第 10 课的 simple_accelerator），X-IF 的延迟更低（不需要经过总线），但设计更复杂（需要和流水线对齐时序）。

## 4. system_bus — 总线的层次结构

### 4.1 两级拆分

```
system_bus
│
├── 9 个 1-to-2 demux (xbar_varlat_one_to_n)
│   每个 master 一个：
│       内部地址 (< 0xF0000000) → system_xbar
│       外部地址 (≥ 0xF0000000) → 外部端口
│
└── system_xbar (onetoM 拓扑，默认)
    ├── xbar_varlat_n_to_one (9 选 1 瓶颈)
    └── xbar_varlat_one_to_n (1 到 7 分发)
         ├── slave 0: Error (0xBADACCE5)
         ├── slave 1: RAM0 (0x00000000)
         ├── slave 2: RAM1 (0x00008000)
         ├── slave 3: Debug (0x10000000)
         ├── slave 4: AO 外设 (0x20000000)
         ├── slave 5: 外设域 (0x30000000)
         └── slave 6: Flash (0x40000000)
```

第 9 课已经详细讲解了 onetoM 的内部结构，这里不再展开。

### 4.2 9 个 master 分别是什么

| 索引 | Master     | 说明                      |
| ---- | ---------- | ------------------------- |
| 0    | CPU 取指   | 指令总线                  |
| 1    | CPU 访存   | 数据总线                  |
| 2    | Debug      | 调试模块                  |
| 3    | DMA 读 0   |                           |
| 4    | DMA 读 1   |                           |
| 5    | DMA 写 0   | 为什么读写各有 2 个端口？ |
| 6    | DMA 写 1   |                           |
| 7    | DMA 地址 0 | 间接寻址用                |
| 8    | DMA 地址 1 |                           |

DMA 需要 2 个读端口 + 2 个写端口是为了**并行传输**：一个通道在从 SPI Flash 读音频数据的同时，另一个通道可以把处理完的数据写到 I2S 输出。

## 5. memory_subsystem — 64 KB SRAM

### 5.1 两个 bank

```
memory_subsystem (2 banks, 各 32 KB)

Bank 0 (RAM0):              Bank 1 (RAM1):
  0x0000_0000 -- 0x0000_7FFF  0x0000_8000 -- 0x0000_FFFF
   ┌──────────┐                 ┌──────────┐
   │ tc_sram  │                 │ tc_sram  │
   │ 8192×32  │                 │ 8192×32  │
   └──────────┘                 └──────────┘
   clk_gate 可独立关            clk_gate 可独立关
```

每个 bank 是 8192 × 32-bit = 32 KB。

第 4 课的链接脚本把代码放在 ram0、数据放在 ram1，就对应这两个 bank。分开的好处：

- 可以把不用的 bank 时钟关掉省电
- 取指令和访问数据可以并行（如果系统总线是 NtoM 模式）

### 5.2 SRAM wrapper 的三个版本

| 版本 | 文件                               | 用途                          |
| ---- | ---------------------------------- | ----------------------------- |
| 仿真 | `hw/simulation/sram_wrapper.sv`  | Verilator 行为模型            |
| FPGA | `hw/fpga/sram_wrapper.sv`        | 映射到 FPGA 的 Block RAM      |
| ASIC | `hw/asic/sky130/sram_wrapper.sv` | 映射到 SkyWater 130nm SRAM 宏 |

同一套顶层 RTL，不同 `sram_wrapper` 实现了跨平台兼容。

## 6. debug_subsystem — 调试链

### 6.1 内部结构

```
debug_subsystem
├── dmi_jtag_i          ← JTAG TAP → DMI 转换
├── dm_obi_top_i        ← 调试模块主体（halt/resume/breakpoint/memory access）
├── obi_spi_slave_i     ← 备选调试通道（SPI slave 代替 JTAG）
├── xbar_varlat_n_to_one_i  ← JTAG vs SPI 二选一仲裁
└── obi_fifo_i          ← 调试主端口的时序隔离
```

### 6.2 两种调试接口

| 接口      | 引脚                              | 用途                 |
| --------- | --------------------------------- | -------------------- |
| JTAG      | TCK, TMS, TRST_N, TDI, TDO (5 根) | 标准调试，接 OpenOCD |
| SPI Slave | SCK, CS, MISO, MOSI (4 根)        | 备选调试，引脚更少   |

通过 SPI 调试时，调试命令经 `obi_spi_slave` 转换成 DMI 信号，和 JTAG 共用同一套 `dm_obi_top`。`xbar_varlat_n_to_one` 仲裁两个来源。

### 6.3 调试模块能做什么

调试模块支持 RISC-V external debug spec v0.13：

- **halt**：暂停 CPU（不管 CPU 在跑什么）
- **resume**：恢复运行
- **单步**：执行一条指令，再 halt
- **读写 CSR**：查看/修改 mcause、mepc 等
- **读写内存**：通过 OBI master 端口访问系统总线上的任意地址
- **硬件断点**：地址匹配触发 halt
- **ndmreset**：非调试模块复位——可以直接复位整个 SoC（除了调试模块自己）

这意味着调试器（通过 JTAG 连的 OpenOCD）**可以在 CPU 被 halt 的时候直接读写 GPIO_OUT0 寄存器**——因为调试模块有独立的 OBI master 端口，不需要 CPU 参与。

## 7. Clock 和 Reset 体系

### 7.1 时钟

```
外部晶振/仿真
     │
  clk_i (100 MHz)
     │
     ├──→ core_v_mini_mcu ──→ CPU、总线、外设（全部同一时钟）
     │         │
     │         ├── power_manager → clk_gate 控制各域的时钟开关
     │         │
     │         └── pdm2pcm 内部有 clk_int_div（独立分频）
     │
     └──→ pad_ring（pad 本身不需要时钟，但 IO 行为对齐此时钟）
```

**没有 PLL 或 DCM**。整个 SoC 只有一个时钟域（100 MHz 仿真 / 50 MHz FPGA），power_manager 通过时钟门控来省电（不是在跑不同的频率，而是把不需要的模块时钟直接关掉）。

唯一的例外是 PDM2PCM，它内部有整数分频器，把系统时钟分到麦克风需要的频率。

### 7.2 复位分发

```
外部复位引脚
     │
  rstgen (glitch-free synchronizer)
     │
     ├──→ core_v_mini_mcu 主复位
     │      │
     │      ├── debug_ndmreset（调试模块可以复位整个 SoC）
     │      │       │
     │      │       ├──→ cpu_subsystem_rst_n ──→ CPU + X-IF
     │      │       ├──→ peripheral_subsystem_rst_n ──→ 外设域
     │      │       └──→ memory banks 各自的复位
     │      │
     │      └── power_manager ──→ 控制每个域的复位断言/解断言
     │
     └──→ pad_ring 复位
```

关键点：**power_manager 可以独立复位每个子系统**。上电序列中，外设域比 CPU 域后解复位——先用 boot_rom 初始化关键外设，再开放对外设域的访问。这解决了"你复位外设的代码和外设一起被复位了"的循环依赖。

## 8. 60 个 IO Pad — 引脚分配与复用

### 8.1 Pad 分类

| 类型      | 数量 | 例子                                                     |
| --------- | ---- | -------------------------------------------------------- |
| 专用功能  | 17   | JTAG(6), CLK, RST, BOOT(2), EXIT, SPI Flash(10 中的部分) |
| 共享/复用 | 43   | GPIO 和 DDR/SPI/I2C/PDM/I2S 共用                         |

### 8.2 复用关系

引脚共享通过 `always_comb` mux 实现。由 `pad_control` 寄存器的 `pad_muxes` 数组控制。

```
Pad          主功能           备用功能
───          ──────           ──────
GPIO[0]      GPIO             （专用）
GPIO[1:3]    GPIO             DDR Serial Link 接收
GPIO[4:5]    GPIO             （专用）
GPIO[6:10]   GPIO             DDR Serial Link 发送
GPIO[11:13]  GPIO             （专用）
GPIO[14:17]  GPIO             SPI Slave (SCK, CS, MISO, MOSI)
GPIO[18:19]  GPIO             PDM2PCM (PDM, CLK)
GPIO[20:22]  GPIO             I2S (SCK, WS, SD)
GPIO[23:29]  GPIO             SPI2 (CS0, CS1, SCK, SD[0:3])
GPIO[30]     GPIO             I2C SCL
GPIO[31]     GPIO             I2C SDA
```

### 8.3 FPGA 上的 pad cell

仿真中的 pad cell 是纯行为模型（组合逻辑直连），但 FPGA 版本的 pad cell 是真的：

```
仿真:  pad_in → wire → pad_out            （零延迟，纯功能）
FPGA:  pad_in → IBUF/OBUF → pad_out       （真实 IO buffer，有时序约束）
ASIC:  pad_in → custom IO cell → pad_out  （模拟/ESD 保护电路）
```

## 9. 参数化配置系统

### 9.1 核心参数文件

`hw/core-v-mini-mcu/include/core_v_mini_mcu_pkg.sv` 约 200 行，定义了整个 SoC 的配置。

### 9.2 关键参数一览

```systemverilog
// ===== 总线 =====
localparam CpuType      = cv32e20;     // CPU 型号（cv32e20/cv32e40p/cv32e40x）
localparam BusType      = onetoM;      // 总线拓扑（onetoM / NtoM）

// ===== 内存 =====
localparam MEM_SIZE     = 64 KB;       // 片上 RAM 总大小
localparam NUM_BANKS    = 2;           // SRAM bank 数

// ===== 外设数量 =====
localparam AO_PERIPHERALS   = 12;      // AO 域外设
localparam PERIPHERALS      = 8;       // 外设域外设

// ===== DMA =====
localparam DMA_CH_NUM            = 4;  // DMA 通道数
localparam DMA_NUM_MASTER_PORTS  = 2;  // DMA 主端口数

// ===== 中断 =====
localparam PLIC_NINT       = 64;       // PLIC 最大中断数
localparam PLIC_USED_NINT  = 52;       // 实际使用的中断数
localparam NEXT_INT        = 12;       // 外部 PLIC 中断数

// ===== 引脚 =====
localparam NUM_PAD         = 60;       // 总 IO 数

// ===== 地址映射 =====
localparam EXT_SLAVE_START_ADDRESS  = 32'hF0000000;
localparam EXT_SLAVE_SIZE           = 32'h01000000;
localparam DEBUG_START_ADDRESS      = 32'h10000000;
localparam AO_PERIPH_START_ADDRESS  = 32'h20000000;
localparam PERIPH_START_ADDRESS     = 32'h30000000;
localparam FLASH_START_ADDRESS      = 32'h40000000;
```

### 9.3 如果改这些参数……

| 修改                   | 影响                                                        |
| ---------------------- | ----------------------------------------------------------- |
| `CpuType = cv32e40x` | CPU 变成 4 级流水、支持 CLIC 中断（硬件自动嵌套），面积翻倍 |
| `BusType = NtoM`     | 9×7 = 63 条内部通路，面积增大但可以同时访问多个 slave      |
| `MEM_SIZE = 128 KB`  | 需要更大的 SRAM，RAM0/RAM1 各 64 KB，地址映射要调整         |
| `DMA_CH_NUM = 8`     | 更多 DMA 通道，但寄存器地址空间要重新分配                   |
| `NUM_BANKS = 4`      | 4 个 bank 各自 16 KB，clock gating 更细粒度                 |

**注意**：修改 `core_v_mini_mcu_pkg.sv` 后需要重新生成 RTL（运行 `make x-heep`），因为某些模块的端口数量取决于这些参数。

构成 X-HEEP 的全部 SystemVerilog 文件按来源分：

| 来源                             | 数量   | 内容                                             |
| -------------------------------- | ------ | ------------------------------------------------ |
| `hw/core-v-mini-mcu/`          | 12 个  | MCU 核心（顶层、子系统、总线）                   |

| `hw/vendor/pulp_platform/`     | ~30 个 | 通用模块（GPIO, crossbar, FIFO, 寄存器接口...）  |
