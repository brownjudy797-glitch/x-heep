## 1. 工具链全景图

X-HEEP 开发需要以下工具，它们各司其职：

```
┌─────────────────────────────────────────────────────┐
│                    X-HEEP 工具链                      │
│                                                      │
│  ┌──────────────┐    ┌──────────────┐               │
│  │ RISC-V GCC   │    │   CMake      │               │
│  │ (编译器)      │    │ (构建系统)    │               │
│  │ C → RISC-V   │    │ 管理编译流程  │               │
│  │ 机器指令      │    │              │               │
│  └──────┬───────┘    └──────┬───────┘               │
│         │                   │                        │
│         └─────────┬─────────┘                        │
│                   ▼                                  │
│            ┌──────────┐                              │
│            │ .elf 文件 │ ← RISC-V 可执行文件           │
│            └─────┬────┘                              │
│                  │ objcopy 转换                      │
│                  ▼                                   │
│         ┌──────────────┐                             │
│         │ .bin / .hex  │ ← 加载到仿真/FPGA 的格式     │
│         └──────┬───────┘                             │
│                │                                     │
│  ┌─────────────┼─────────────┐                      │
│  │             ▼             │                      │
│  │  ┌──────────────────┐    │                      │
│  │  │ FuseSoC + Verilator│   │                      │
│  │  │ (硬件构建 + 仿真)   │   │                      │
│  │  │ RTL → 仿真可执行文件│   │                      │
│  │  └────────┬─────────┘    │                      │
│  │           ▼              │                      │
│  │  ┌──────────────────┐    │                      │
│  │  │ GTKWave          │    │                      │
│  │  │ (波形查看)        │    │                      │
│  │  └──────────────────┘    │                      │
│  └──────────────────────────┘                      │
└─────────────────────────────────────────────────────┘
```

**工具分工**：

- `riscv32-unknown-elf-gcc`：把 C 代码编译成 RISC-V 机器码
- `cmake`：管理固件的编译过程（哪个文件、什么选项、链接顺序）
- `fusesoc`：管理硬件的构建过程（哪个 RTL 文件、什么参数、用什么仿真器）
- `verilator`：把 SystemVerilog RTL 转换成 C++ 仿真模型并执行
- `gtkwave`：查看仿真产生的波形文件

## 2. 安装 RISC-V GCC 工具链

### 2.1 关键要求：multilib 支持

X-HEEP 需要编译 `rv32imc/ilp32` 目标。你的 GCC 工具链必须支持这一 multilib 组合，否则链接时会报错：

```
Cannot find suitable multilib set for '-march=rv32imc_zicsr'/'-mabi=ilp32'
```

可以用以下命令检查工具链支持的 multilib：

```bash
<your-gcc> -print-multi-lib
```

如果只输出一行 `.;`，说明不支持 `rv32imc/ilp32`，需要更换工具链。

### 2.2 推荐方式：xPack 预编译工具链

已验证可直接用于 X-HEEP：

```bash
# 下载 xPack 嵌入式 RISC-V 工具链
wget https://github.com/xpack-dev-tools/riscv-none-elf-gcc-xpack/releases/download/v13.3.0-1/xpack-riscv-none-elf-gcc-13.3.0-1-linux-x64.tar.gz

# 解压
tar xzf xpack-riscv-none-elf-gcc-13.3.0-1-linux-x64.tar.gz

# 安装到 /opt（与 X-HEEP CMake 脚本默认路径一致）
sudo rm -rf /opt/riscv32-toolchain/riscv
sudo mkdir -p /opt/riscv32-toolchain/riscv
sudo cp -r xpack-riscv-none-elf-gcc-13.3.0-1/* /opt/riscv32-toolchain/riscv/

# 验证 multilib（应该输出多行）
/opt/riscv32-toolchain/riscv/bin/riscv-none-elf-gcc -print-multi-lib
```

> 注意：xPack 的编译器前缀是 `riscv-none-elf-`，不是 `riscv32-unknown-elf-`。

### 2.3 不推荐：系统包管理器安装

```bash
# Ubuntu 24 的 gcc-riscv32-unknown-elf 是 GCC 16.x，默认 ABI 为 ilp32d
# 且只构建了一个 multilib，不支持 X-HEEP 需要的 rv32imc/ilp32 组合
sudo apt install gcc-riscv32-unknown-elf  # 不推荐
```

### 2.4 关键编译选项

X-HEEP 编译时使用以下选项：

| 选项 | 含义 |
|------|------|
| `-march=rv32imc_zicsr` | 32 位 + 整数 + 乘法 + 压缩指令 + CSR 操作 |
| `-mabi=ilp32` | int/long/pointer 均为 32 位 |
| `-O2` | 优化级别 2（平衡速度和代码大小） |

> CV32E40P 不支持浮点（F/D 扩展），必须使用 `-mabi=ilp32`。GCC 13+ 需要显式指定 `_zicsr`（CSR 指令扩展），旧版本自动包含在 I 中。

## 3. 安装 Verilator

Verilator 是一个**开源的高性能 SystemVerilog 仿真器**。它把 RTL 代码先编译成 C++，再编译成原生可执行文件——所以仿真速度比传统解释型仿真器（如 Icarus Verilog）快很多。

### 3.1 安装

**Ubuntu/Debian**：

```bash
sudo apt update
sudo apt install verilator
```

**验证**：

```bash
verilator --version
```

期望输出类似：

```
Verilator 5.020 ...
```

### 3.2 Verilator 工作原理

```
SystemVerilog RTL ──→ Verilator ──→ C++ 模型 ──→ g++ ──→ 仿真可执行文件
     (.sv)              (编译)        (.cpp)       (编译)      (运行)
```

这意味着：

- **首次编译**较慢（RTL → C++ → 二进制），但**仿真执行**很快
- 修改 RTL 后需要重新编译；修改固件（.hex）后一般只需重新仿真

## 4. 安装 GTKWave

GTKWave 是开源的**数字波形查看器**，用于查看 Verilator 生成的 `.fst` 或 `.vcd` 波形文件。

```bash
sudo apt install gtkwave
```

验证：

```bash
gtkwave --version
```

> 备选：`gtkwave` 比较老旧，也可以考虑使用 [Surfer](https://gitlab.com/surfer-project/surfer)（Rust 写的现代波形查看器，更快的渲染速度）。

## 5. 安装 FuseSoC

FuseSoC 是一个**硬件包管理和构建系统**。它的核心概念是：

- `.core` 文件描述一个硬件模块（它有哪些 RTL 文件、依赖哪些其他模块、提供哪些参数）
- FuseSoC 根据 `.core` 文件自动收集所有需要的 RTL 文件、处理依赖关系、调用仿真器

### 5.1 安装（使用项目虚拟环境）

先在 X-HEEP 目录下创建 Python 虚拟环境，再在其中安装 FuseSoC。这样不会污染系统 Python，也避免 Ubuntu 24.04 的 pip 限制。

```bash
cd /path/to/x-heep
python3 -m venv .venv
source .venv/bin/activate
pip install fusesoc
fusesoc --version
```

为了方便，把激活命令加到 `~/.bashrc`：

```bash
echo 'source /path/to/x-heep/.venv/bin/activate' >> ~/.bashrc
```

### 5.2 注册 X-HEEP 到 FuseSoC

```bash
cd /path/to/x-heep
fusesoc library add x-heep .
```

验证注册成功：

```bash
fusesoc core list | grep x-heep
```

预计会看到大约 35 个 WARNING（Parse error），全部来自 OpenTitan 上游库的基础元件 `.core` 文件使用了旧版 FuseSoC 格式。这些 **warning 可以安全忽略**——X-HEEP 不直接依赖这些受损的 core 文件，仿真不受影响。

## 7. 第一次固件编译

### 7.1 设置环境变量

X-HEEP 的构建系统依赖以下环境变量：

```bash
export RISCV_XHEEP=/opt/riscv32-toolchain/riscv
export COMPILER_PREFIX=riscv-none-
export COMPILER=gcc
export ARCH=rv32imc_zicsr
```

建议写入 `~/.bashrc` 永久生效：

```bash
cat >> ~/.bashrc << 'EOF'

# X-HEEP development
export RISCV_XHEEP=/opt/riscv32-toolchain/riscv
export COMPILER_PREFIX=riscv-none-
export COMPILER=gcc
export ARCH=rv32imc_zicsr
EOF
source ~/.bashrc
```

### 7.2 了解一个 application 的结构

看 `sw/applications/example_gpio_toggle/`：

```bash
ls sw/applications/example_gpio_toggle/
```

典型内容：

```
CMakeLists.txt   ← 告诉 CMake 怎么编译这个应用
main.c           ← 应用源码
```

CMakeLists.txt 示例（简化）：

```cmake
add_application(
  NAME example_gpio_toggle
  SOURCES main.c
)
```

### 7.3 编译（推荐用顶层 Makefile）

```bash
cd /path/to/x-heep
make app PROJECT=example_gpio_toggle
```

这个命令会自动处理 CMake 配置，传递正确的 `PROJECT`、`LINKER`、`ARCH` 等参数。

> 如果手动运行 cmake，必须传 `-DPROJECT=<name>` 和 `-DLINKER=on_chip`，否则会配置失败。

编译成功后，产物在 `sw/build/` 下：

```
sw/build/
├── main.elf     ← RISC-V 可执行文件（所有 app 都输出为 main.elf）
├── main.bin     ← 纯二进制
├── main.hex     ← Intel HEX 格式
└── main.map     ← 内存布局文件
```

构建输出末尾会显示内存占用信息：

```
Total space: 64.0 kB
Bank        Start      End   Sz(kB)  Usd(kB)  Req(kB)  Utilz(%)    Contents
ram0:         0.0     58.0     58.0      6.0      6.0      10.3    Code (C), ROData (R)
ram1:        58.0     64.0      6.0      4.9      4.9      82.0    Data (d)
```

### 7.4 检查编译产物

```bash
# 注意：xPack 工具前缀是 riscv-none-elf-，不是 riscv32-unknown-elf-
RISCV_PREFIX=/opt/riscv32-toolchain/riscv/bin/riscv-none-elf-

# 查看 ELF 文件信息
${RISCV_PREFIX}readelf -h main.elf

# 反汇编，找 main 函数
${RISCV_PREFIX}objdump -d main.elf | grep -A20 '<main>:'

# 查看段大小
${RISCV_PREFIX}size main.elf
```

典型的 size 输出：

```
   text    data     bss     dec     hex filename
   2048      64     128    2240     8c0 main.elf
```

| 段 | 含义 |
|------|------|
| `.text` | 代码段（指令），放在 RAM 中执行 |
| `.data` | 已初始化的全局变量，启动时复制到 RAM |
| `.bss` | 未初始化的全局变量（启动时清零），在 RAM 中 |
| `.stack` | 栈空间，在 RAM 中 |

## 8. 工具链自检脚本

把以下内容保存为 `check_env.sh`，运行确认所有工具可用：

```bash
#!/bin/bash

check() {
    if command -v "$1" &> /dev/null; then
        echo "✓ $1: $(command -v $1)"
    else
        echo "✗ $1: NOT FOUND"
    fi
}

echo "=== X-HEEP 工具链检查 ==="
echo ""

check riscv-none-elf-gcc
check verilator
check gtkwave
check fusesoc
check cmake
check ninja
check python3

echo ""
echo "=== 版本信息 ==="
riscv-none-elf-gcc --version 2>/dev/null | head -1
verilator --version 2>/dev/null
gtkwave --version 2>/dev/null | head -1
fusesoc --version 2>/dev/null
cmake --version 2>/dev/null | head -1

echo ""
echo "=== Multilib 检查 ==="
riscv-none-elf-gcc -print-multi-lib 2>/dev/null
```

运行：

```bash
bash check_env.sh
```

## 常见踩坑记录

### Q: 编译报 `Cannot find suitable multilib set`

你的 GCC 不支持 `rv32imc/ilp32` 组合。用 `-print-multi-lib` 检查，如果只输出一行 `.;`，需要换 xPack 工具链（见 2.2 节）。

### Q: 汇编报 `unrecognized opcode 'csrw', extension 'zicsr' required`

GCC 13+ 把 CSR 指令从基础 `I` 扩展中分离了，需要在 `ARCH` 中加上 `_zicsr`：

```bash
export ARCH=rv32imc_zicsr
```

### Q: CMake 报 `if given arguments: "STREQUAL" "on_chip"`

手动 cmake 时缺少 `-DPROJECT=` 和 `-DLINKER=` 参数。推荐直接用顶层 Makefile：

```bash
make app PROJECT=example_gpio_toggle
```

### Q: pip 安装报 `externally-managed-environment`

使用项目虚拟环境安装 Python 包（见 5.1 节）：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install fusesoc
```

### Q: FuseSoC 出现大量 `Parse error` WARNING

全部来自 OpenTitan 上游库的旧版 `.core` 文件，可以安全忽略，不影响仿真。
