## 1. sw/ 目录全景

```
sw/
├── applications/        ← ★ 所有用户应用程序
├── device/
│   ├── lib/
│   │   ├── crt/         ← C 运行时启动代码（crt0.S、vectors.S）
│   │   ├── base/        ← 基础函数（mmio 读写、memory 操作）
│   │   ├── drivers/     ← ★ 外设 HAL 驱动（gpio、uart、i2c、spi...）
│   │   ├── runtime/     ← 运行时支持（heap、syscalls、handler）
│   │   └── sdk/         ← ★ 高层 SDK（在 HAL 之上封装）
│   ├── bsp/             ← 板级支持包（特定硬件板子的配置）
│   └── target/          ← ★ 目标平台头文件（sim、fpga 等，每平台一个 x-heep.h）
├── freertos/            ← FreeRTOS 移植与配置
├── linker/              ← ★ 链接脚本（link.ld、link_flash_load.ld）
├── vendor/              ← 第三方代码
├── cmake/               ← CMake 工具链文件（riscv.cmake）
├── build/               ← 构建输出目录
├── Makefile             ← 构建入口
└── CMakeLists.txt       ← ★ 顶层 CMake 配置
```

各模块的分层关系：

```
┌────────────────────────────────────────────┐
│           applications/                     │  ← 你的代码
│        main() 在这，调用 SDK / HAL          │
├────────────────────────────────────────────┤
│              sdk/                           │  ← 高层封装
│      i2c_sdk, spi_sdk, timer_sdk...         │     屏蔽外设细节
├────────────────────────────────────────────┤
│            drivers/                         │  ← HAL 驱动
│   gpio, uart, i2c, spi, dma, rv_plic...    │     直接操作寄存器
├────────────────────────────────────────────┤
│              base/                          │  ← 基础操作
│        mmio_read32 / mmio_write32           │     裸寄存器读写
├────────────────────────────────────────────┤
│       硬件寄存器（MMIO）                     │
│     0x40000000 → GPIO, 0x40001000 → UART   │
└────────────────────────────────────────────┘
```

### 2.2 application 内部结构

以 `example_gpio_toggle` 为例：

```
example_gpio_toggle/
└── main.c          ← 只有这一个文件
```

它的 `main.c` 核心逻辑（简化版）：

```c
#include "core_v_mini_mcu.h"   // MCU 公共头文件
#include "gpio.h"              // GPIO HAL 驱动头文件
#include "x-heep.h"            // 目标平台配置（时钟频率、UART 波特率等）

int main(int argc, char *argv[])
{
    gpio_cfg_t pin_cfg = {
        .pin = 2,                      // 用 GPIO 引脚 2
        .mode = GpioModeOutPushPull    // 推挽输出模式
    };
    gpio_config(pin_cfg);              // 初始化 GPIO

    for (int i = 0; i < 100; i++) {
        gpio_write(2, true);   // 拉高
        for (int j = 0; j < 10; j++) asm volatile("nop");
        gpio_write(2, false);  // 拉低
        for (int j = 0; j < 10; j++) asm volatile("nop");
    }
    return 0;
}
```

三个关键头文件的作用：

| 头文件                | 作用                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------- |
| `x-heep.h`          | 目标平台定义（时钟频率、引脚数、`TARGET_SIM` 宏等），**不同 target 用不同版本** |
| `core_v_mini_mcu.h` | MCU 通用常量（外设基地址、中断号等）                                                    |
| `gpio.h`            | GPIO HAL 驱动 API 声明                                                                  |

## 3. device/ 目录 — 驱动的三层架构

### 3.1 base/ — 最底层：MMIO 操作

`device/lib/base/mmio.c` 提供最基础的寄存器读写，例如：

```c
// 向地址 addr 写入 32 位值
void mmio_region_write32(mmio_region_t base, ptrdiff_t offset, uint32_t value);

// 从地址 addr 读取 32 位值
uint32_t mmio_region_read32(mmio_region_t base, ptrdiff_t offset);
```

所有 HAL 驱动最终都通过这两个函数操作硬件寄存器。

### 3.2 drivers/ — HAL 驱动层

每个外设一个子目录，包含 `.c` 和 `.h` 文件：

```
drivers/
├── gpio/gpio.c, gpio.h           ← GPIO 驱动
├── uart/uart.c, uart.h           ← UART 驱动
├── i2c/i2c.c, i2c.h              ← I2C 驱动
├── spi_host/spi_host.c, spi_host.h  ← SPI 主机驱动
├── dma/dma.c, dma.h              ← DMA 驱动
├── rv_plic/rv_plic.c, rv_plic.h  ← 平台级中断控制器 (PLIC)
├── rv_timer/rv_timer.c, rv_timer.h  ← RISC-V Timer
├── power_manager/...             ← 电源管理
├── soc_ctrl/...                  ← SoC 控制（时钟频率、复位原因等）
└── ...
```

HAL 驱动的工作模式（以 GPIO 为例）：

```
gpio_config()                         ← 用户调用
  └→ mmio_region_write32(             ← HAL 内部
        GPIO_BASE_ADDR,                ← 外设基地址（在 core_v_mini_mcu.h 中定义）
        GPIO_CFG_REG_OFFSET,           ← 寄存器偏移（由 regtool.py 生成）
        cfg_value                      ← 写入的位域值
     )
       └→ 最终变成一条 RISC-V sw 指令 → OBI 总线写事务 → GPIO 硬件模块
```

### 3.3 sdk/ — 高层封装

在 HAL 之上进一步封装，让外设操作更简单：

```
sdk/
├── i2c_sdk/    ← I2C 高层 API（封装了 DMA + I2C 的复杂交互）
├── spi_sdk/    ← SPI 高层 API
├── spi_slave_sdk/
├── timer_sdk/
└── dma_sdk/
```

对比 HAL vs SDK：

```c
// HAL 层：操作细粒度，需要手动管理
i2c_write(addr, data, len);
while (!i2c_is_tx_complete());   // 手动等待

// SDK 层：高层封装，自动处理 DMA 和等待
i2c_sdk_write(addr, data, len);  // 函数内部帮你等
```

### 3.4 crt/ — C 运行时启动

`crt0.S` 是 MCU 上电后执行的第一段代码（在 C 的 `main()` 之前）：

```
_start:
  设置 gp (全局指针)     → 用于访问 .sdata / .sbss 的短地址
  设置 sp (栈指针)       → 指向链接脚本中定义的 _sp
  设置 CPU 频率寄存器     → 告知硬件 REFERENCE_CLOCK_Hz
  清零 .bss 段           → 未初始化全局变量 = 0
  设置 mtvec (中断向量)   → 指向中断向量表
  调用 C 构造函数         → __libc_init_array
  调用 main()            → 终于进入 C 世界
  调用 exit()            → main 返回后
```

`vectors.S` 定义了中断向量表，每个中断入口跳转到对应的 handler。

## 4. target/ — 目标平台配置

`device/target/` 下每个子目录对应一个运行平台，每个都有自己的 `x-heep.h`：

```
target/
├── sim/          ← Verilator 仿真
├── pynq-z2/      ← TUL Pynq-Z2 FPGA 板
├── nexys-a7-100t/ ← Digilent Nexys-A7 FPGA 板
├── zcu104/       ← Xilinx ZCU104
├── genesys2/     ← Genesys2
└── ...
```

以仿真 target（`target/sim/x-heep.h`）为例：

```c
#define REFERENCE_CLOCK_Hz (100*1000*1000)  // 仿真用 100MHz
#define UART_BAUDRATE (REFERENCE_CLOCK_Hz / 20)
#define TARGET_SIM 1                        // 标记当前是仿真模式
#define MAX_PIN     32                      // 最大 GPIO 引脚数
```

不同 target 的差异：

| 配置项             | sim     | pynq-z2 | nexys-a7-100t |
| ------------------ | ------- | ------- | ------------- |
| REFERENCE_CLOCK_Hz | 100 MHz | 50 MHz  | 100 MHz       |
| TARGET_SIM         | 1       | 0       | 0             |
| MAX_PIN            | 32      | 32      | 32            |

构建时通过 `-DTARGET=sim` 参数选择 target，CMake 自动 include 对应的 `x-heep.h`。

## 5. linker/ — 链接脚本与内存布局

### 5.1 链接脚本的作用

链接脚本告诉链接器：**代码和数据放在内存的哪个位置**。

X-HEEP 提供多种链接脚本：

```
linker/
├── link.ld               ← 全部在 RAM 中运行（仿真用）
├── link_flash_load.ld    ← 从 Flash 加载到 RAM
└── link_flash_exec.ld    ← 在 Flash 中原地执行
```

第 2 课我们用 `-DLINKER=on_chip` 对应 `link.ld`。

### 5.2 link.ld 关键内容解读

```ld
MEMORY
{
    ram0 (rwxa) : ORIGIN = 0x000000, LENGTH = 0x00e800   // 58 KB，放代码和只读数据
    ram1 (rwxa) : ORIGIN = 0x00e800, LENGTH = 0x001800   // 6 KB，放可读写数据
}
```

```
0x000000 ┌──────────────┐
         │  .vectors    │  中断向量表
         │  .init       │  启动代码（固定地址 0x180）
         │  .text       │  程序代码 ← ram0 (58 KB)
         │  .rodata     │  只读数据（字符串常量等）
0x00e800 ├──────────────┤
         │  .data       │  已初始化全局变量
         │  .bss        │  未初始化全局变量 ← ram1 (6 KB)
         │  .heap       │  动态分配（malloc）
         │  .stack      │  栈空间
0x010000 └──────────────┘
```

几个关键符号（在 crt0.S 中使用）：

| 符号                            | 定义位置 | 作用                                       |
| ------------------------------- | -------- | ------------------------------------------ |
| `_start`                      | crt0.S   | 程序入口（链接脚本指定 `ENTRY(_start)`） |
| `__boot_address`              | link.ld  | 启动地址 = 0x180                           |
| `_sp`                         | link.ld  | 栈顶（栈向下增长）                         |
| `__bss_start` / `__bss_end` | link.ld  | BSS 段范围，启动时清零                     |
| `__global_pointer$`           | link.ld  | 全局指针，用于短地址访问                   |

### 5.3 编译后的内存占用解读

编译输出末尾的内存报告：

```
Total space: 64.0 kB
Bank        Start      End   Sz(kB)  Usd(kB)  Req(kB)  Utilz(%)    Contents
ram0:         0.0     58.0     58.0      6.0      6.0      10.3    Code (C), ROData (R)
ram1:        58.0     64.0      6.0      4.9      4.9      82.0    Data (d)
```

- **ram0**：代码 + 只读数据占 6 KB，利用率 10.3%
- **ram1**：数据段接近满（82%），因为包含了 stack 和 heap

## 6. CMake 构建流程

### 6.1 构建命令回顾

```bash
cd /home/rime/x-heep
make app PROJECT=example_gpio_toggle
```

这条命令背后发生了什么：

```
1. 顶层 Makefile 解析参数
   PROJECT=example_gpio_toggle
   TARGET=sim（默认）
   LINKER=on_chip（默认）
   ARCH=rv32imc_zicsr（环境变量）

2. 调用 sw/Makefile
   传递所有变量给 CMake

3. CMake 配置阶段
   - 读取 sw/CMakeLists.txt
   - 找到 applications/example_gpio_toggle/
   - 收集所有 .c/.S/.cpp 源文件
   - 根据 TARGET 选择对应的 x-heep.h
   - 根据 LINKER 选择对应的 link.ld
   - 设置编译选项 (-march=..., -mabi=..., -O2 等)

4. CMake 生成阶段
   - 生成 Makefile

5. CMake 构建阶段
   - 编译所有源文件 → .obj
   - 链接 → main.elf
   - 生成 main.bin, main.hex
```

### 6.2 源文件收集规则

CMakeLists.txt 自动收集文件，不需要手动列出每个 .c：

```
CONDITION                        收集的源文件
─────────────────────────────────────────────────
所有 project                     device/lib/crt/*.S（启动代码）
所有 project                     device/lib/base/*.c（mmio、memory）
所有 project                     device/lib/drivers/ 全部驱动
所有 project                     device/lib/runtime/*（syscalls、heap）
所有 project                     device/lib/sdk/ 全部 SDK
所有 project                     applications/${PROJECT}/ 下的 .c/.cpp/.S
freertos project                 额外加上 freertos/ 下的源文件
```

### 6.3 编译选项解释

从构建日志中可以看到实际使用的编译选项：

```
-march=rv32imc_zicsr       ← RISC-V 指令集架构
-mabi=ilp32                ← ABI（32-bit int/long/pointer）
-O2                        ← 优化级别
-g                         ← 包含调试信息
-nostartfiles              ← 不链接标准 C 启动文件（用自定义 crt0.S）
-ffunction-sections        ← 每个函数放独立 section（方便链接器优化）
-DON_CHIP                  ← 宏：在芯片上运行（非 Flash 加载模式）
-DHOST_BUILD               ← 宏：在开发机上编译
```

## 7. 实践：新增一个 application

### 7.1 创建目录和源码

```bash
mkdir -p /home/rime/x-heep/sw/applications/my_first_app
```

创建 `my_first_app/main.c`：

```c
#include <stdio.h>
#include <stdlib.h>

#include "core_v_mini_mcu.h"
#include "x-heep.h"

int main(int argc, char *argv[])
{
    printf("My first X-HEEP app!\n");
    printf("CPU frequency: %d Hz\n", REFERENCE_CLOCK_Hz);

    return EXIT_SUCCESS;
}
```

### 7.2 编译

```bash
cd /home/rime/x-heep
make app PROJECT=my_first_app
```

### 7.3 验证

```bash
# 查看是否生成
ls -la sw/build/main.elf

# 反汇编确认
riscv64-unknown-elf-objdump -d sw/build/main.elf | grep -A15 '<main>:'
```

> 注意：不需要手动创建 CMakeLists.txt，X-HEEP 的顶层 CMakeLists.txt 会自动扫描 `applications/${PROJECT}/` 目录。
