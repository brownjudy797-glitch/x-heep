## 1. 中断 vs 异常

### 1.1 区别

| | 中断 | 异常 |
|---|---|---|
| **触发源** | 外部硬件（GPIO 引脚变化、UART 收完数据、Timer 到点） | CPU 内部（非法指令、访问越界、ecall） |
| **时机** | 异步：随时可能发生 | 同步：某条指令执行时触发 |
| **返回地址** | `mepc` = 尚未完成的第一条指令 | `mepc` = 触发异常的指令（需要修复或跳过） |
| **典型例子** | 按键按下、串口收到数据 | 除以零、空指针解引用、断点 |

在 RISC-V 中，中断和异常用同一个 trap 机制处理——都通过 `mtvec` 指定的入口跳转到 handler。

### 1.2 RISC-V 异常原因表（mcause）

| mcause | 类型 | 含义 |
|--------|------|------|
| 1 | 异常 | 取指访问错误 |
| 2 | 异常 | 非法指令 |
| 3 | 异常 | 断点（ebreak） |
| 5 | 异常 | Load 访问错误 |
| 7 | 异常 | Store 访问错误 |
| 8 | 异常 | 环境调用（U-mode ecall） |
| 11 | 异常 | 环境调用（M-mode ecall） |
| 3 | 中断 | 软件中断（irq_software） |
| 7 | 中断 | 定时器中断（irq_timer） |
| 11 | 中断 | 外部中断（irq_external，来自 PLIC） |
| 16-31 | 中断 | 快速中断（irq_fast[15:0]） |

## 2. 全图：中断如何从外设到 CPU

```
外设                    中断控制器               CPU
─────                   ──────────              ───

GPIO[31:8] ──→  ┌── UART (8)                  
UART       ──→  │   GPIO (24)                  
I2C        ──→  │   I2C (16)       irq_external    
SPI2       ──→  ├─→ PLIC ─────────────→ bit 11 ──┐
I2S        ──→  │   SPI2 (1)        (外部中断)     │
Flash      ──→  │   I2S (1)                       │
外部中断   ──→  │   Flash (1)                       │
                │   外部 (12)                       │
                └── 共 64 输入                      │   ┌─────────┐
                                                    ├─→│ CPU     │
GPIO_AO[7:0]──→ ┌── GPIO_AO (8)         irq_fast   │   │ cv32e20 │
DMA done   ──→  │   DMA done (1)     ─────────→    │   │         │
DMA window ──→  │   DMA window (1)   bits 16-31    │   │ trap →  │
Timer[3:1] ──→  ├─→ fast_intr_ctrl ───────────────→│   │ handler │
SPI        ──→  │   SPI (1)           16 个快速     │   │         │
SPI Flash  ──→  │   SPI Flash (1)    中断通道       │   │ mret ◄─ │
外部 fast  ──→  │   外部 fast (1)                   │   └─────────┘
                └── 共 16 输入                      │
                                                    │
Timer[0]   ─────────────────────────────→ bit 7 ────┘
Software   ─────────────────────────────→ bit 3 ────┘
```

**两个层级**：
- **PLIC**（Platform-Level Interrupt Controller）：负责"常规中断"——UART、I2C、GPIO[31:8] 等。支持优先级、支持 claim/complete 流程、通过一条 `irq_external` 线连到 CPU
- **fast_intr_ctrl**：负责"快速中断"——GPIO_AO[7:0]、DMA、Timer[3:1]、SPI。无优先级、直接输出 pending 向量（16 条独立线连到 CPU）

## 3. CPU 内部：从 trap 到 handler

### 3.1 关键的 CSR 寄存器

RISC-V 用几个特殊寄存器控制 trap：

| CSR | 全称 | 作用 |
|-----|------|------|
| `mtvec` | Machine Trap Vector | trap 入口地址（crt0.S 设置为 `__irq_vector`） |
| `mepc` | Machine Exception PC | trap 发生时被中断的指令地址 |
| `mcause` | Machine Cause | 原因码（上一节的表） |
| `mtval` | Machine Trap Value | 附加信息（如非法地址） |
| `mstatus` | Machine Status | 全局中断使能（MIE bit） |
| `mie` | Machine Interrupt Enable | 各中断源的使能位 |

### 3.2 硬件自动做的事（trap 时）

```
1. mepc ← PC            // 保存被中断的指令地址
2. mcause ← 原因码       // 写入中断/异常原因
3. mtval ← 附加信息      // 如非法地址
4. mstatus.MPIE ← mstatus.MIE  // 保存旧的中断使能状态
5. mstatus.MIE ← 0      // 关闭中断（默认不嵌套）
6. PC ← mtvec           // 跳到中断向量表
```

整个过程是硬件在一条指令的边界上自动完成的，软件不需要（也不能）参与。

### 3.3 mret 做了什么

handler 最后执行 `mret`：

```
1. mstatus.MIE ← mstatus.MPIE  // 恢复中断使能
2. PC ← mepc                    // 跳回被中断的地址
```

硬件自动做，软件只需要在 handler 中保证 `mepc` 没被破坏。

## 4. 中断向量表：vectors.S

### 4.1 裸机 interrupt vector

`sw/device/lib/crt/vectors.S` 定义了 32 个 4 字节的 entry：

```asm
.section .vectors, "ax"
.balign 0x100       // 256 字节对齐（mtvec 要求）

__irq_vector:
    j handler_exception           // entry 0  (mcause=0)：异常
    j handler_exception           // entry 1
    j handler_exception           // entry 2
    j handler_irq_software        // entry 3  (mcause=3)：软件中断
    j handler_exception           // entry 4
    j handler_exception           // entry 5
    j handler_exception           // entry 6
    j handler_irq_timer           // entry 7  (mcause=7)：定时器中断
    // ...
    j handler_irq_external        // entry 11 (mcause=11)：外部中断（PLIC）
    // ...
    j handler_irq_fast_timer_1    // entry 16 (mcause=16)：快速中断 0
    j handler_irq_fast_timer_2    // entry 17
    // ... 一直到 entry 31
```

### 4.2 为什么 base 是 0x100 而不是 0x0

地址 0x0 到 0x100 被启动代码（crt0.S）占了。`mtvec` 需要 256 字节对齐（vectored 模式下最低 2 bit 是 mode），所以 `__irq_vector = 0x100` 是一个合理选择。

### 4.3 条件编译的部分

部分快速中断的 entry 不是永远存在的——取决于 X-HEEP 的配置：

```asm
#if DMA_IS_INCLUDED
    j handler_irq_fast_dma_done     // entry 19
#endif
```

如果 DMA 没有被编译进 SoC，对应的 entry 就变成普通的 exception handler，不会分配快速中断号。

## 5. C 语言 handler：handler.c

### 5.1 弱函数覆盖机制

所有 handler 都声明为 `__attribute__((weak))`：

```c
// handler.c 中的默认实现
__attribute__((weak)) void handler_irq_timer(void) {
    printf("Timer IRQ\n");
    while(1);  // 死循环 — 如果不覆盖，来一个 timer 中断就卡住
}
```

应用代码可以定义同名函数覆盖它：

```c
// 在 main.c 中
void handler_irq_timer(void) {
    static int ticks = 0;
    ticks++;
    rv_timer_clear_interrupt();  // 清除中断
}
```

链接器优先链接非 weak 的定义，所以应用代码覆盖了默认实现。

### 5.2 异常 handler

```c
void handler_exception(void) {
    uint32_t mcause;
    asm volatile("csrr %0, mcause" : "=r"(mcause));

    switch (mcause) {
        case 2:  // 非法指令
            printf("Illegal instruction at %p\n", mepc);
            break;
        case 11: // ecall from M-mode
            printf("ECALL from M-mode\n");
            break;
        // ...
    }
    while(1);
}
```

## 6. PLIC 深入

### 6.1 PLIC 的四个关键操作

```
软件操作              硬件行为
────────              ────────
1. 设置优先级        每个中断源有 3-bit 优先级（0-7，0 = 禁止）
2. 设置阈值          PLIC 只响优先级 > 阈值的中断
3. claim（读）       读 claim 寄存器，获取当前最高优先级的待处理中断 ID
                     PLIC 硬件清除相应 pending 位
4. complete（写）    写中断 ID 到 complete 寄存器
                     PLIC 硬件清除该中断的 claim 状态
```

### 6.2 一个完整的 PLIC 中断周期

```
时间线：
  外设                    PLIC                    CPU                       软件
  ────                    ────                    ───                       ────
  1. GPIO 引脚变化  →  intrs[23] = 1   →  irq_plic = 1  →  trap!
  2.                                                        handler_irq_external()
  3.                                                        plic_irq_claim()
  4.                               ← claim_addr 被读 ←
  5.                               → 返回 ID=23
  6.                                                        handlers[23]()
  7.                                                        plic_irq_complete(23)
  8.                               ← complete_addr 写 ID=23 ←
  9.           清除该源的 claim
```

**关键理解**：从 claim 到 complete 这段时间，同一优先级的中断被阻塞。如果来了更高优先级的中断，**会不会打断当前 handler？** 不会——因为 `mstatus.MIE` 在 trap 时被硬件清零了，handler 执行期间全局中断关闭。X-HEEP 默认不支持中断嵌套。

### 6.3 PLIC 中断源分配（64 个输入）

PLIC 有 64 个中断输入，X-HEEP 连了 52 个：

| ID 范围 | 数量 | 来源 |
|---------|------|------|
| 0 | 1 | 保留（连到 0） |
| 1-8 | 8 | UART |
| 9-32 | 24 | GPIO[31:8]，每个引脚一个 |
| 33-48 | 16 | I2C |
| 49 | 1 | SPI2 event |
| 50 | 1 | I2S event |
| 51 | 1 | Flash 控制器 |
| 52-63 | 12 | 外部中断（NEXT_INT=12） |

### 6.4 PLIC 驱动代码

`sw/device/lib/drivers/rv_plic/rv_plic.c`：

```c
// 注册 handler
void plic_set_handler(uint8_t id, plic_handler_t handler) {
    handlers[id] = handler;
    plic_enable_int(id);
    plic_set_priority(id, 1);
}

// 外部中断入口
void handler_irq_external(void) {
    uint32_t id = plic_irq_claim();
    if (id > 0 && handlers[id] != NULL)
        handlers[id]();
    plic_irq_complete(id);
}
```

## 7. 快速中断 vs PLIC：本质区别

| | PLIC | fast_intr_ctrl |
|---|---|---|
| **通道数** | 64 个输入 | 16 个输入 |
| **到 CPU 的线** | 1 条（irq_external） | 16 条（irq_fast[15:0]） |
| **优先级** | 有（3-bit，0-7） | 无，完全扁平 |
| **获取原因** | claim 读寄存器（多拍） | 直接读 pending 寄存器（1 拍） |
| **完成通知** | 写 complete（多拍） | 写 clear 寄存器（1 拍） |
| **延迟** | ~5-10 拍 | ~1-2 拍 |
| **RTL 代码量** | 数千行（OpenTitan） | ~150 行 |

**为什么需要两种？** PLIC 灵活但慢——claim/complete 都是 MMIO 操作，一次要好几拍。对于唤醒信号（GPIO_AO 需要在上电后尽快被感知）和实时外设（DMA 完成需要马上启动下一段传输），延迟太大会丢数据。fast_intr_ctrl 用硬件直连 + 最短路径，保证延迟最低。

## 8. 中断嵌套问题

### 8.1 默认不支持嵌套

trap 时 `mstatus.MIE` 被硬件清零。handler 执行期间，即使更高优先级的中断来了，CPU 也不会理。

**如果想支持嵌套怎么办？** 在 handler 中手动软件开中断：

```c
void handler_irq_external(void) {
    asm volatile("csrsi mstatus, 8");  // MIE = 1，允许嵌套
    // ... 处理 ...
    asm volatile("csrci mstatus, 8");  // MIE = 0
}
```

但这样做危险：嵌套意味着 handler 可能被中断、再次进入 handler、栈上压多层帧——需要足够大的栈空间。MCU 的栈通常不大，X-HEEP 默认保守策略（不嵌套）是合理的。

| 通道 | 来源 | 用途 |
|------|------|------|
| 0 | 外部 fast 中断 | FPGA 扩展 |
| 1 | DMA window | DMA 2D 传输窗口事件 |
| 2-9 | GPIO_AO[7:0] | 每个 AO 引脚独立中断 |
| 10 | SPI Flash | Flash 操作完成 |
| 11 | SPI Host | SPI 传输完成 |
| 12 | DMA done | DMA 传输完成 |
| 13-15 | RV Timer[3:1] | Timer 1/2/3 中断 |

## 10. 实践：GPIO 中断驱动 LED 翻转

### 10.1 应用代码模板

```c
#include "core_v_mini_mcu.h"
#include "gpio.h"
#include "x-heep.h"

// 覆盖弱函数
void handler_irq_fast_gpio_2(void) {
    gpio_write(2, !gpio_read(2));  // 翻转输出
    gpio_clear_interrupt(2);       // 清除中断 pending
}

int main(void) {
    // 1. 配置 GPIO 2 为输出
    gpio_cfg_t out_cfg = {.pin = 2, .mode = GpioModeOutPushPull};
    gpio_config(out_cfg);

    // 2. 配置 GPIO 3 为输入，使能上升沿中断
    gpio_cfg_t in_cfg = {
        .pin = 3,
        .mode = GpioModeInPullDown,
        .intr_enable = GpioIntrRiseEdge
    };
    gpio_config(in_cfg);

    // 3. 使能全局中断
    asm volatile("csrsi mstatus, 8");  // MIE = 1

    // 4. 主循环什么都不做，等中断
    while (1) {
        asm volatile("wfi");
    }
}
```

### 10.2 关键步骤总结

1. 配置外设的中断条件（沿/电平）
2. 使能外设的中断输出
3. 使能 PLIC 或 fast_intr_ctrl 中的对应位
4. 使能 CPU 的全局中断（`mstatus.MIE`）
5. 在 handler 中**清除中断源**（否则中断一直 pending，CPU 会反复 trap）
