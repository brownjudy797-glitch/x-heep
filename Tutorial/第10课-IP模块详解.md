## 1. 全景：X-HEEP 有哪些 IP

### 1.1 AO 域 vs 外设域

回顾第 5 课的内容：X-HEEP 把外设分成两个域。

| | AO 域（Always-On） | 外设域（可关断） |
|---|---|---|
| **电源** | 不掉电 | 休眠时可关断 |
| **时钟** | `clk_i` 直通 | `clk_cg`（可门控） |
| **外设数** | 12 个 | 8 个 |
| **基地址** | `0x20000000` | `0x30000000` |

### 1.2 AO 域 12 个外设

| # | 外设 | 基地址 | 一句话职责 |
|---|------|--------|-----------|
| 0 | `soc_ctrl` | `0x20000000` | 芯片 ID、启动选择、时钟频率 |
| 1 | `boot_rom` | `0x20010000` | 59 条预编码启动指令 |
| 2 | `spi_flash` | `0x20020000` | OpenTitan SPI Flash 控制器 |
| 3 | `spi_memio` | — | SPI 内存映射 IO |
| 4 | `w25q128jw_controller` | — | Winbond Flash 控制器 |
| 5 | `dma_subsystem` | `0x20030000` | 4 通道 DMA |
| 6 | `power_manager` | `0x20040000` | 电源域开关、休眠唤醒 |
| 7 | `rv_timer_ao` | `0x20050000` | Timer 0 & 1 |
| 8 | `fast_intr_ctrl` | `0x20060000` | 16 通道快速中断 |
| 9 | `ext_peripheral` | — | 外部设备接口 |
| 10 | `pad_control` | `0x20080000` | 引脚复用 |
| 11 | `gpio_ao` | `0x20090000` | GPIO 引脚 0-7 |

### 1.3 外设域 8 个外设

| # | 外设 | 基地址 | 一句话职责 |
|---|------|--------|-----------|
| 0 | `rv_plic` | `0x30000000` | 平台级中断控制器（优先级、路由） |
| 1 | `spi_host` | `0x30010000` | SPI 主机 1 |
| 2 | `gpio` | `0x30020000` | GPIO 引脚 8-31 |
| 3 | `i2c` | `0x30030000` | I2C 主机 |
| 4 | `rv_timer` | `0x30040000` | Timer 2 & 3 |
| 5 | `spi2` | `0x30050000` | SPI 主机 2 |
| 6 | `i2s` | — | I2S 音频 |
| 7 | `uart` | `0x30080000` | 串口 |

### 1.4 为什么这样分配

AO 域放的是**掉电后还要工作的东西**：
- `power_manager` 在 AO 域——因为关电的控制器自己不能掉电
- `gpio_ao` 在 AO 域——用作休眠时的唤醒源
- `dma_subsystem` 在 AO 域——允许 DMA 在 CPU 休眠时继续搬运数据

外设域放的是**可以一起关掉的外围接口**——UART、SPI、I2C 这些通信接口休眠时不需要工作，关掉省电。

## 2. DMA 子系统

### 2.1 整体架构

```
                ┌──────────────────────────────────────┐
                │           dma_subsystem               │
                │                                      │
  OBI bus ──────┤→ reg_demux ──→ Ch0 / Ch1 / Ch2 / Ch3 │
                │                                      │
                │  Ch0 ──→ [N→M xbar] ──→ Master Port 0 │
                │  Ch1 ──→              ──→ Master Port 1 │
                │  Ch2 ──→                          │
                │  Ch3 ──→                          │
                └──────────────────────────────────────┘
```

X-HEEP 默认配置：4 个 DMA 通道，2 个 OBI 主端口。4 个通道通过内部 N→M crossbar 共享 2 个主端口。

每个通道占 0x100 字节地址空间。`reg_demux` 根据地址 `[15:8]` 把寄存器访问路由到对应通道：
- Ch0: offset 0x000-0x0FF
- Ch1: offset 0x100-0x1FF
- Ch2: offset 0x200-0x2FF
- Ch3: offset 0x300-0x3FF

### 2.2 单通道内部结构

```
┌─────────────┐    ┌──────────┐    ┌───────────┐    ┌─────────────┐
│ read_unit   │──→ │ buffer   │──→ │ processing│──→ │ write_unit  │
│ (OBI 读)    │    │ (FIFO)   │    │ (padding) │    │ (OBI 写)    │
└─────────────┘    └──────────┘    └───────────┘    └─────────────┘
      ↑                                                    │
      └──────────── read_addr_unit (可选) ─────────────────┘
```

**read_unit**：从源地址读数据，支持 1D/2D 地址生成
**buffer_unit**：深度 4 的 FIFO，解耦读端和写端
**processing_unit**：2D 零填充（top/left/right/bottom）
**write_unit**：写数据到目标地址，生成字节使能
**read_addr_unit**（可选，`ADDR_MODE_EN`）：读地址与读数据分离

### 2.3 主 FSM（3 状态）

```
DMA_READY ──→ DMA_STARTING ──→ DMA_RUNNING ──→ DMA_READY
   ↑                              │
   └──── circular mode ───────────┘
```

- **DMA_READY**：空闲，等待 `dma_start_pending`
- **DMA_STARTING**：单拍脉冲，锁存传输参数（源地址、目标地址、长度、步长）
- **DMA_RUNNING**：数据传输中，等待 `dma_done`
- **circular mode**：完成后自动跳回 `DMA_STARTING`，用于连续音频流等场景

### 2.4 读写单元的 OBI 握手子 FSM

```systemverilog
// 在 read_unit 和 write_unit 中各有一份
OBI_DATA_REQ:    // 发出 req，等待 gnt
OBI_WAIT_GNT:    // 已发出 req 但 slave 还没 gnt，保持信号不变
```

这跟第 9 课讲的 OBI 握手是一模一样的——`req` 保持到 `gnt = 1` 为止。

### 2.5 2D 传输与零填充

1D 传输：源地址 → 目标地址，连续拷贝 N 个字。

2D 传输：在二维数组间拷贝，源和目标的**行步长**可以不同。

```
源数组 3×3              目标数组 5×5（零填充）
┌───┬───┬───┐           ┌───┬───┬───┬───┬───┐
│ A │ B │ C │           │ 0 │ 0 │ 0 │ 0 │ 0 │  ← top padding
├───┼───┼───┤           ├───┼───┼───┼───┼───┤
│ D │ E │ F │    →      │ 0 │ A │ B │ C │ 0 │  ← left + right padding
├───┼───┼───┤           ├───┼───┼───┼───┼───┤
│ G │ H │ I │           │ 0 │ D │ E │ F │ 0 │
└───┴───┴───┘           ├───┼───┼───┼───┼───┤
                         │ 0 │ G │ H │ I │ 0 │
                         ├───┼───┼───┼───┼───┤
                         │ 0 │ 0 │ 0 │ 0 │ 0 │  ← bottom padding
                         └───┴───┴───┴───┴───┘
```

填充 FSM（`dma_processing_unit.sv`）有 9 个状态：

```
PAD_IDLE → TOP_PAD_EXEC → TOP_PAD_DONE
         → LEFT_PAD_EXEC → LEFT_PAD_DONE
         → 正常数据行
         → RIGHT_PAD_EXEC → RIGHT_PAD_DONE
         → BOTTOM_PAD_EXEC → BOTTOM_PAD_DONE
         → PAD_IDLE
```

每一行先插左填充（N 个零），再拷贝有效数据，再插右填充。所有数据行处理完后插底部填充行。

### 2.6 Trigger 机制

每个 DMA 通道有若干个 **trigger slot**。外设（如 SPI 的 RX FIFO 非空）通过 slot 触发 DMA 传输，实现**硬件同步**——不需要 CPU 轮询。

这是 DMA 最有价值的特性：CPU 配好参数，DMA 自己等外设的 trigger，到了就搬数据，搬完发中断。

### 2.7 传输模式小结

| 模式 | `mode` 值 | 行为 |
|------|-----------|------|
| 普通 | 0 | 一次传输，完成后回 READY |
| Circular | 1 | 自动循环，用于音频流等 |
| Address | 2 | 从地址 FIFO 读取目标地址（间接寻址） |
| Subaddr | 3 | 字节/半字粒度 |

## 3. 电源管理器（power_manager）

### 3.1 管理的电源域

```
                    ┌─────────────────┐
CPU 子系统 ─────────│ pwr_gate        │ ← 电源开关
                    │ iso             │ ← 隔离（防止掉电后不确定值传播）
                    │ reset           │ ← 复位
                    └─────────────────┘

外设子系统 ─────────│ pwr_gate        │
                    │ iso             │
                    │ reset           │
                    │ clk_gate        │ ← 时钟门控
                    └─────────────────┘

RAM Bank 0/1 ───────│ switch          │ ← 电源开关
                    │ iso             │
                    │ clk_gate        │
                    │ retentive       │ ← 保持模式（数据不丢失）
                    └─────────────────┘

DMA Ch 0-3 ──────── clk_gate 独立控制
```

"隔离"（isolation）是什么？当一个电源域掉电后，其输出的逻辑值变得不确定。如果这些不确定值馈入仍然上电的域，会导致短路或逻辑错误。隔离单元在掉电侧插入，把输出箝位到安全值。

### 3.2 三层嵌套 FSM

CPU 子系统的电源序列化是最复杂的，用了三层嵌套：

```
第 1 层: reg_to_counter     (3 状态)
         RESET → IDLE → COUNTING
         倒计时到零 → 发脉冲

第 2 层: counter_sequence   (7 状态)  ← 每个控制信号一个
         RESET → IDLE → WAIT_OFF_COUNTER → SWITCH_OFF
                      → WAIT_ON_COUNTER → WAIT_ACK → SWITCH_ON
         用 reg_to_counter 做定时

第 3 层: power_manager.sv   协调 reset / switch / iso 三个 counter_sequence
         按正确的顺序启动它们
```

外设域和 RAM 域用简化的 **power_manager_sequence**（5 状态，无计数器延迟）：

```
RESET → IDLE → WAIT_SWITCH_ON → WAIT_ACK → SWITCH_ON
```

因为外设域的开关不需要精细的时序控制（CPU 域需要保证电源稳定的等待时间）。

### 3.3 CPU 休眠上电序列

**休眠（下电）**：`WFI → power_gate_core → core_sleep`

```
1. 断言复位     (等待 cpu_reset_assert_counter 拍)
2. 关闭电源开关 (等待 cpu_switch_off_counter 拍)
3. 打开隔离     (等待 cpu_iso_off_counter 拍)
   → CPU 域完全掉电
```

**唤醒（上电）**：`中断 → start_on_sequence`

```
1. 关闭隔离     (等待 cpu_iso_on_counter 拍)
2. 打开电源开关 (等待 cpu_switch_on_counter 拍)
3. 等待供电稳定 (cpu_wait_ack_switch_on)
4. 解除复位     (等待 cpu_reset_deassert_counter 拍)
   → CPU 从 WFI 之后的第一条指令继续执行
```

每个计数器的值由软件通过寄存器配置，允许针对不同工艺/电压做调优。

### 3.4 中断状态监控

`intr_state` 寄存器收集 32 个中断源，包括 GPIO、SPI、DMA、Timer、PLIC 的中断。当 `en_wait_for_intr` 使能后，任意活跃中断都会触发上电序列——这就是"按键唤醒"或"定时唤醒"的硬件基础。

## 4. 快速中断控制器（fast_intr_ctrl）

### 4.1 与 PLIC 的对比

| | fast_intr_ctrl | rv_plic (PLIC) |
|---|---|---|
| **通道数** | 16 | 可配置（数十个） |
| **优先级** | 无，完全扁平 | 支持优先级 |
| **目标路由** | 无，单输出 | 支持多 hart 多目标 |
| **中断 ID** | 无，直接输出 pending 向量 | 有，claim/complete 机制 |
| **延迟** | 组合逻辑输出（< 1 拍） | 需要读 claim 寄存器（多拍） |
| **复杂度** | ~200 行 RTL | 来自 OpenTitan，数千行 |
| **适用场景** | 唤醒 + 低延迟快速响应 | 复杂中断管理 |

### 4.2 硬件设计

```systemverilog
// 16 个通道，用 for 循环生成
for (genvar i = 0; i < 16; i++) begin : gen_fast_intr_channels
    // 每个通道：
    //   interrupt_i[i] → set pending
    //   fast_intr_set[i] → set pending（软件触发）
    //   fast_intr_clear[i] → clear pending
    //   enable[i] → 门控输出
end

// 输出：直接连线
assign fast_intr_o = reg2hw.fast_intr_pending.q;
```

没有任何 FSM，没有任何握手。中断源到中断输出的路径只有组合逻辑（经过一个 AND 门做 enable 门控）。

`fast_intr_o` 直接连到 CPU 的快速中断输入，绕过了 PLIC 的优先级仲裁和 claim/complete 流程。

### 4.3 三个寄存器

| 寄存器 | 偏移 | 读写 | 功能 |
|--------|------|------|------|
| `fast_intr_pending` | 0x0 | R/W | 读：当前 pending 状态。写 1：软件触发中断 |
| `fast_intr_clear` | 0x4 | W1C | 写 1 清除对应 pending 位 |
| `fast_intr_enable` | 0x8 | R/W | 使能掩码 |

## 5. PDM2PCM 音频通路

### 5.1 整体数据流

```
PDM 麦克风 ──→ [CIC 滤波器] ──→ [第一级 Halfband] ──→ [第二级 Halfband] ──→ [FIR] ──→ PCM 输出
                ↓                 ↓                       ↓                      ↓
           降采样 + 滤波       2× 降采样               2× 降采样              最终整形
```

PDM（Pulse Density Modulation）是数字 MEMS 麦克风的标准输出格式——1 bit 的高频比特流。PCM（Pulse Code Modulation）是标准的音频采样格式——16/18 bit 的多位采样。这条链路的任务就是把前者转成后者。

### 5.2 CIC 滤波器

CIC（Cascaded Integrator-Comb）是最简单的降采样滤波器——没有乘法器，只有加法器和寄存器。

```
CIC Integrator（积分器）：y[n] = y[n-1] + x[n]
CIC Comb（梳状器）：      y[n] = x[n] - x[n-D]
```

X-HEEP 支持最多 4 级 CIC。级数由 `cic_activated_stages` 的 thermometric 掩码选择：
- `6'b000001` → 1 级
- `6'b000011` → 2 级
- `6'b000111` → 3 级
- `6'b001111` → 4 级

更多级数 = 更好的阻带衰减 = 更多面积和延迟。

CIC 后面接一个可配置的降采样器（`decimator`），每 N 个输入产生一个输出。

**为什么用 thermometric 码而不是二进制？** 这样选择每一级的 MUX 只需要看单 bit，不需要译码——省逻辑。

### 5.3 Halfband + FIR

**Halfband 滤波器**：系数对称，一半系数为零。一个 10 阶 halfband 只有 3 个非零系数需要乘法。

```
系数示例: [0, c1, 0, c3, 0.5, c5, 0, c3, 0, c1, 0]
             ↑ 零    ↑ 零    ↑        ↑ 对称于中心
```

X-HEEP 用了 **两级 halfband**，每级后面跟 2× 降采样。两级后采样率降到原来的 1/4。

**FIR 滤波器**：最后一级 26 阶 FIR，系数对称且可编程，用于最终的频谱整形。

### 5.4 双时钟域

```
clk_i ────────────────────────────────────────────
            │
            ├── 寄存器接口（软件读写配置）
            │
            └── clk_int_div ──→ div_clk ─────────
                                    │
                                    ├── CIC
                                    ├── Halfband
                                    └── FIR

         CDC FIFO (gray code) 桥接两个时钟域
```

`clkdividx` 寄存器决定降频比。比如系统时钟 100 MHz，`clkdividx = 10` → PDM 采样时钟 = 10 MHz → 实际麦克风时钟（`pdm_clk_o` 输出）约为 5 MHz。

`pdio_in` 是麦克风的 1-bit 数据输入。硬件把它映射：0 → -1（全 1 的补码），1 → +1。

### 5.5 CIC-only 模式

当不需要高质量音频时，可以通过 `control` 寄存器关闭 halfband 和 FIR——综合工具会把这两级完全优化掉，节省大量面积。

## 6. boot_rom — 第一条指令从哪来

### 6.1 里面是什么

boot_rom 只有 **59 个 32-bit 字**（236 字节），内容是 RISC-V 机器码。

```
boot_rom 做的事情：
1. 设置栈指针
2. 配置 GPIO（用于指示启动阶段）
3. 初始化 SPI Flash
4. 从 Flash 加载用户程序到 RAM
5. 跳到 RAM 中的用户程序入口
```

第 4 课学的 crt0.S 是**软件启动代码**（在 RAM 中、由用户程序链接），boot_rom 是**硬件启动代码**（在 ROM 中、上电就跑、不可改）。

### 6.2 硬件接口

```systemverilog
// 组合逻辑读，无时钟无复位
assign read_data = mem[addr];
assign ready = 1'b1;
assign error = 1'b0;
```

最简单的 OBI slave——零等待，永远就绪。读越界返回 0。

## 7. soc_ctrl — 系统控制寄存器

### 7.1 寄存器一览

| 寄存器 | 偏移 | 功能 |
|--------|------|------|
| `exit_valid` | 0x00 | 软件写 1 → 仿真结束退出 |
| `exit_value` | 0x04 | 退出码（0 = 正常） |
| `boot_select` | 0x08 | 只读，反映硬件 boot 引脚状态 |
| `boot_exit_loop` | 0x0C | 仿真专用：Verilator 可 force 此位退出 boot 循环 |
| `boot_address` | 0x10 | 可配置启动地址（预留） |
| `use_spimemio` | 0x14 | 选择 SPI Flash 控制器 vs SPI 内存映射 |
| `enable_spi_sel` | 0x18 | 软件可覆盖 SPI 片选 |
| `system_frequency_hz` | 0x1C | 只读，系统时钟频率 |
| `xheep_id` | 0x20 | 只读，芯片 ID |
| `xheep_ao_peripheral_config` | 0x24 | 只读，AO 域外设配置 |
| `xheep_peripheral_config` | 0x28 | 只读，主域外设配置 |

### 7.2 关键设计点

`soc_ctrl` 没有 FSM——纯粹是寄存器到硬件信号的映射。

`xheep_id` 的实现是个特例：不是通过通用的 regtool 寄存器接口，而是直接比较地址：

```systemverilog
// soc_ctrl.sv
assign direct_xheep_id_access = (reg_req_i.addr == SOC_CTRL_XHEEP_ID_OFFSET)
                                && !reg_req_i.write;
```

读 `xheep_id` 时返回硬件输入的 `xheep_instance_id_i` 信号——这个值在综合时由顶层参数决定，每个芯片实例可以有不同的 ID。写则被忽略。

`boot_exit_loop` 在仿真中特别重要：boot_rom 启动后等待 Flash 就绪，但在 RTL 仿真中没有真实的 Flash 延迟，Verilator testbench 可以 force 这个寄存器来跳过等待循环。

## 8. 总线缓冲：obi_fifo

### 8.1 为什么深度只有 1

第 9 课提到过 `obi_fifo` 用于时序隔离。这里深入看内部设计。

obi_fifo 内部有**两个独立 FSM**：

**Producer FSM（面向 master 一侧）**：
```
PRODUCER_REQUEST        ← 正常状态：接收 req，推入 FIFO
PRODUCER_WAIT_FOR_VALID ← 已 gnt 一个请求但 rvalid 还没回来
                          阻塞新请求，保证 OBI 的无 outstanding 约束
```

**Consumer FSM（面向 slave 一侧）**：
```
CONSUMER_REQUEST      ← FIFO 有数据就发 req
CONSUMER_WAIT_FOR_GNT ← 已发 req 但 slave 还没 gnt
                         保持所有信号不变（OBI 握手协议要求）
```

两个 FSM 各管一边，通过两个深度-1 FIFO（请求 FIFO 和响应 FIFO）通信。

**为什么深度只有 1？** 因为 OBI 不支持 outstanding 事务。如果深度 > 1，master 发出第二个请求但第一个还没响应时，FIFO 里会堆积请求，但 OBI 没有事务 ID 来匹配响应——回来的是谁的 rdata 就分不清了。深度 1 天然保证了一次只飞一个事务。

### 8.2 在哪用了

AO 外设子系统和外设子系统的入口各有一个 obi_fifo（可通过 `REMOVE_OBI_FIFO` 宏去掉）。

放在子系统入口的原因是：子系统内部有多个外设的地址译码和寄存器逻辑，组合路径长。obi_fifo 在入口处切断这条路径，让 xbar → 子系统 的时序更容易收敛。

## 9. 实践：手写一个简单加速器

### 9.1 simple_accelerator 模板

X-HEEP 提供了 `hw/ip_examples/simple_accelerator/` 作为自定义 IP 的参考模板。它演示了：

1. **寄存器接口**：通过 reg_req/reg_rsp 与 OBI 总线对接
2. **OBI 主端口**：加速器可以自己读写内存（像 DMA 一样）
3. **FSM 控制**：READY → STARTING → RUNNING

### 9.2 寄存器定义

| 地址 | 寄存器 | 位宽 | 功能 |
|------|--------|------|------|
| 0x00 | `address_read` | 32 | 源地址 |
| 0x04 | `address_write` | 32 | 目标地址 |
| 0x08 | `threshold` | 32 | 阈值 |
| 0x0C | `status_ready` | 1 | 读：就绪？写：清除就绪 |
| 0x10 | `size` | 10 | 传输长度（字） |
| 0x14 | `status_start` | 1 | 写 1 启动 |

### 9.3 计算核心（一行代码的加速器）

```systemverilog
// simple_accelerator.sv 的计算逻辑
data_out_wdata = data_out_wdata > threshold_q ? data_out_wdata : threshold_q;
```

这是一个"下限裁剪"：所有低于阈值的值都替换为阈值。一行组合逻辑，但被包装成符合 X-HEEP IP 模板的完整模块——有寄存器接口、有 OBI 读/写主端口、有 FSM。

### 9.4 读写单元的 OBI 主端口

加速器的读/写单元和第 2 节 DMA 的读/写单元是同一套代码（`dma_read_unit.sv`、`dma_write_unit.sv`）。这说明 X-HEEP 的 IP 设计高度模块化——任何需要主动读写内存的 IP 都可以复用 DMA 的读写单元。

要创建自定义加速器，你需要做的：
1. 复制 `simple_accelerator`
2. 替换计算逻辑（那一行 `data_out_wdata = ...`）
3. 添加新的寄存器（如果需要配置参数）
4. 在顶层例化并连接

## 10. peripheral_subsystem vs ao_peripheral_subsystem 结构对比

### 10.1 ao_peripheral_subsystem 的额外复杂度

```
ao_peripheral_subsystem
├── OBI FIFO（入口缓冲）
├── reg_mux ← 仲裁主总线 + SPC 端口的访问
├── 12 个外设
├── spi_subsystem ← 内部复用 SPI Flash / SPI Memio / Flash 控制器
└── DMA 的 N→M crossbar
```

AO 域比外设域多了：
- **SPC 端口仲裁**：系统电源控制器可以通过专属端口访问 AO 外设，不经过主总线
- **SPI 子系统**：在 SPI Flash 和 SPI Memio 之间做二选一
- **DMA crossbar**：4 通道 2 端口的 N→M 仲裁

外设域就简单多了——一个 OBI FIFO，一个地址译码器，8 个外设一字排开。
